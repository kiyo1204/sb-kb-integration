# リンク端点のドラッグ・付け替え案内

2026-11-13、main `374dd22d2eb21e619e2fd49b14a6011cafb31676` を基点とする。
参考: [Kit-Buildマニュアル](https://lel.main.jp/kb/subf/data/KBmanual.pdf) 6ページ「マップの組み立て」。左右の丸をドラッグして概念につなぐ操作を参考にした。マニュアルにある未接続状態の保存や正誤表示は取り込まない。

## 調査・範囲

Issue #29・#30・#33・#34はopen。PR #37のSVGクリック領域修正とは別の、端点の丸と操作案内だけの改善。PR #41の始点・矢印の先、候補強調、矢印プレビューとEsc中止を再利用する。別worktreeの未コミット「統合追加要素の強調」は保持し、本変更へ取り込まない。

変更前のEdge/1440×1000実画面（合成API応答）では、保存済みリンクを選択しても端点名の表示が0件だった。丸は18px、端点名はドラッグ中だけ表示される構成だった。

- 保存済みリンクの選択時にも始点・矢印の先を表示し、短い付け替え手順を出す。
- 丸を26pxにしてつかみやすくする。ドラッグ中の候補・方向は既存処理を維持。
- 概念以外へのドロップ・中止時に、保存済み接続を変えていないことを既存の案内領域で表示する。
- 未接続リンクは保存しない。新規リンクは両端が接続された時だけ既存APIへ送信。既存リンクを空白に離した場合は元の接続を保つ。切り離したまま保存するにはDB/API契約変更が必要なため実装しない。

backend製品コード、保存方向、重複・接続制約、操作ログ、キャンセル種別、Undo/Redo、提出、タイマー・Merge・分析・Exportは変更しない。新しい正誤情報は出さない。

## 検証方法

新規使い捨てPostgreSQL `stage1_mock_endpoint_drag` を作成し、既存migrationを適用。既存 `verifyMockTestUrl` で専用DBを照合して、loopbackの製品APIを起動する。通常公開は閉じたまま、専用プロセスだけ既存の模擬preview設定を使用。合成教材は3概念・1リンク、1800秒の時間はfixtureのみで研究条件や既定値ではない。

既存 `test:link-direction-api` を拡張し、授業→SB→KB→統合を製品APIで準備して各Mapを実学習者認証のEdgeで操作する。画面再読込時は既存の研究者端末切替を利用。API応答の差替え・通常認証の迂回はしない。画面は1440×1000、Windows/Node 24.15.0。

新規接続、始点・終点それぞれの付け替え、実GETと最終SQLによる保存方向、無効ドロップとEscで変更要求が出ないこと、画面Undo/Redo、再読込を確認する。KBの全体キャンセルはIMPORT_KIT_LINK、通常リンクはADD_LINKの既存CANCELLED記録であり、Map変更と区別する。Esc・無効ドロップに新しいイベント種別を追加しない。

合成APIによる `test:link-direction-browser` は新protocol SB/KB/統合、旧4活動SB・旧5活動KB・旧6活動統合の代表6ケースを確認する。実DBの検証とは区別する。関連回帰は `test:link-position-browser`、`test:five-flow-feedback-browser`。全体suiteはローカルで再実行しない。

## 途中の失敗

- 新worktreeの権限制限でtsbuildinfoへの書込みが失敗した試行と、書込み可能な環境でのfrontend型検査・Lint・build成功を区別する。backend型検査・Lint・buildも成功。
- KBのキャンセルをADD_LINKとして待った検証はタイムアウト。IMPORT_KIT_LINKへ修正した。
- Undo/Redo後の画面再取得を待たない操作と、KBの画面外の端点操作を修正し、実際の表示位置・処理完了を待ってマウス操作する。
- SBから複製した概念と統合検証用概念の重複配置を解消した。方向・保存処理の不具合と混同しない。

画面画像は環境変数による指定先またはOS一時領域へ保存し、PRには含めない。依存パッケージ導入時の既存audit警告と、frontendの既存bundleサイズ警告は今回の製品変更で修正しない。実機LAN、物理的な複数端末、初見利用者による操作評価、既存DBへの適用、本番運用は未確認。

最終結果: 実APIのSB・KB・統合MapすべてPASS。合成APIの代表6ケースとリンク位置・KB/統合フィードバックの関連回帰もPASS。backend/frontend型検査・Lint・build、`git diff --check`成功。統合MapのSQL照合は新規リンク成功1件、始点・終点の再接続成功2件、全体キャンセル1件を確認。端末切替を伴うfixtureで表示される観測イベントの送信待ちはMap保存とは別であり、送信待ち全件の完了や回収を保証しない。

専用DBはID・用途・nonceで照合し、コンテナー・volume・manifestを削除した。元worktreeの追加要素強調表示や既存バックアップは変更しない。
