# ゴールマップ JSON 書き出し・取込み

研究者はゴールマップ管理画面から JSON を書き出し、別環境で新しいゴールマップとして取り込めます。既存マップは更新しません。取込時に `maps`、`concepts`、`links` の新しい内部IDを発行し、同じ概念・リンク表を使う Kit を作成します。Kit には取込マップ内の概念・リンクを登録するため、新しい Session の初期概念選択から利用できます。

## JSON形式

```json
{
  "format": "sb-kb-goal-map",
  "schemaVersion": 1,
  "goalMap": {
    "title": "光合成の仕組み",
    "concepts": [
      { "id": "concept-1", "label": "光", "position": { "x": 120, "y": 80 } },
      { "id": "concept-2", "label": "糖", "position": { "x": 520, "y": 80 } }
    ],
    "links": [
      { "id": "link-1", "label": "を生み出す", "sourceId": "concept-1", "targetId": "concept-2", "labelPosition": { "x": 320, "y": 100 } }
    ]
  }
}
```

`concepts[].id` と `links[].id` はファイル内だけで使う参照IDです。エクスポートにはDB UUIDを含めず、インポート時に参照関係を保って内部IDへ置き換えます。`sourceId` から `targetId` への向きと、概念座標・リンクラベル座標を保持します。リンクラベル座標が自動配置の場合は `labelPosition: null` です。

Session、学習者、P-ID、イベント履歴、回答、認証情報、Kit ID、DB参照は形式に含めません。未知フィールドを含むJSONは拒否します。

## サーバー検証

- フォーマット名・schemaVersion、必須フィールド、厳密な型とフィールド集合
- ファイル全体4,000,000 bytes、概念1,000件、リンク2,000件
- タイトル120文字、概念・リンクのラベル512文字、座標の絶対値10,000,000以内
- ファイル内IDの形式と重複、リンク接続先の存在
- 既存のマップラベル検証によるURL・認証情報などの拒否。保存済み学習者アクセスコードも照合
- 重複タイトルはHTTP 409で拒否し、ファイル内のタイトル変更を案内

取込APIは認証済み研究者に限定します。マップ、概念、リンク、Kit、Kit項目は一つのDBトランザクションで作成し、失敗時は全てロールバックします。既存DB変更や追加マイグレーションはありません。

## 検証記録

`stage1_mock_goal_final` という新規の専用模擬DBで全マイグレーションを適用し、追加のマイグレーションなしで機能を確認しました。対象suiteは **5/5成功** です。書出し・取込み・再書出し、ノードとリンクの向き・座標、内部ID再割当て、元マップ不変、一覧表示、Session作成時のKit概念選択、2つの別Sessionの学習者トークン拒否を確認しました。無効JSON、未知項目、破損リンク、ID重複、名前重複、概念・リンク数、文字列・全体サイズ超過、未認証要求、研究者・学習者アクセスコード入り文字列、DB故障注入による全件ロールバックも拒否・確認しました。Suite結果は [goal-map-transfer-suite-results.json](goal-map-transfer-suite-results.json) に記録しています。

backend/frontendの型検査・Lint・ビルドは **6/6成功** です。全体suiteは今回の対象外として再実行していません。別の `db:mock check` は検証結果に含めていません。seed前は開発Kit不在、seed後は同チェックの空イベント履歴の前提を満たせず失敗したためです。今回の対象suiteは専用DB上で成功し、作成した模擬DBコンテナーとmanifest/cacheをすべて削除しました。
