## 共通箇所での判断

- 練習ブラウザーテストは、補足文非表示に加えて、新規KBが空で全パーツがパレットに揃うことを確認する。既存の進捗復元・方向・再判定、フィードバックの結果表示、P08関連の503受信後の表示確認も残す。
- MapPageのリンク作成案内は、統合マップに「名称」を使い、ゴールマップの作成モードに応じて手順を出し分ける。リンクのアクセシブル名は、移動できる場合だけドラッグを案内する。実験本編は既存のハンドル役割で接続する。
- 本編リンク方向の実ブラウザーテストは、SBと統合でそれぞれの正確な入力欄名を指定する。初回は統合画面でも旧ラベルを探してタイムアウトしたため、操作・保存値・方向のアサーションを維持して入力欄の指定を修正した。
- ゴールマップのラベル位置保存は、研究者・マップ所属・Kit未登録の条件をテストする。実験本編のリンク位置保存は既存の操作履歴へ記録する。イベント契約・出力処理・マイグレーションは基準コミットのまま。

## 検証と復旧

練習ブラウザースイート全体、本編のリンクとKBフィードバック、ゴール編集と拒否条件、練習APIのDB不変検証、型検査、対象ESLintと差分を確認する。APIはループバックに限定した専用模擬DBと人工データで実行する。共有画面の回帰を見つけた場合は該当テストを再実行する。変更を取り消す場合は統合先の該当差分を戻す。DB復旧や元ツリーの変更は不要。

## PR #97 レビュー対応

- KB練習では確定済みの接続を判定に使う。保存済みリンクの両端解除から再接続が完了するまで判定ボタンと送信を止め、取消時は確定済みの接続で再び判定できる。修正前は両端解除中にも判定要求が送られ、正解を解除した画面で HTTP 200 と一致が返った。
- ゴールマップの再試行は、マップID・編集の種類・対象IDごとに保持する。位置保存と接続保存は応答と必要な再取得まで順に処理する。修正前はリンク2件の座標保存を続けて失敗させると、先に失敗した編集の再試行が消えた。
- Edgeの練習ブラウザースイートで、両端解除中・片端接続中に判定を送信せず、取消と再接続の後に表示どおりの接続を判定した。専用模擬DBを使うゴールマップのブラウザーテストでは、概念位置・リンク位置・接続それぞれで2件の失敗を個別に再試行でき、再読込で保存を確認した。リンク位置の保存応答を保留した間の再試行とドラッグも止められた。
- 既存課題（P3）: KB本編の判定応答を待つ間に Escape で閉じると、応答の到着時に結果ダイアログが再び開き、フォーカスが移る。基準コミットにも同じ経路がある。
